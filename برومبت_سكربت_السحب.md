## How to find old items (RSS will NOT work for 2023)
Try these discovery methods per source, in this order, and keep whichever works:
1. The site's own sitemaps (sitemap index, date-based or news sitemaps, robots.txt Sitemap lines).
2. GDELT 2.0 raw files (GKG or Events, 15-minute files for the date range): extract item URLs whose domain matches the source.
3. Wayback Machine CDX API: list captured URLs for the domain within the date range.
4. The site's archive or section pages with pagination.
Then fetch each item: live first, Wayback snapshot as fallback. Extract text with trafilatura (newspaper4k as fallback). Take the publish date from page metadata (JSON-LD, meta tags), not from the fetch date.

## Phase 2: full pull
- Resumable (can stop and restart without duplicating work), with a progress log.
- Polite: respect robots.txt, max ~1 request/second per domain, retries with backoff, a descriptive User-Agent naming an academic research project (do not put any email in it).

## Storage
SQLite database (articles.db).

Table articles:
- id, source_id, url, canonical_url
- title, subtitle (lead paragraph if present), text
- published_at (ISO, with timezone), updated_at (if the page shows a modification date)
- language, category, scope_match (which rule matched, or "all")
- content_type: one of news, report, opinion, analysis, interview, live_blog, press_release, video, infographic, unknown
- content_type_signals: the raw evidence used (JSON-LD @type such as NewsArticle / OpinionNewsArticle / AnalysisNewsArticle / ReportageNewsArticle / LiveBlogPosting, URL path like /opinion/ or /مقالات/ or /آراء/, site section name, meta tags)
- authors: list of author names as written (from JSON-LD author, meta author, or the byline); empty list if none
- author_raw: the byline text exactly as it appears
- agency_credit: any news agency credited in the byline or dateline (e.g. وفا، رويترز، فرانس برس، الأناضول، Reuters, AP, AFP); empty if none
- site_section, tags (as the site lists them)
- discovery_method, fetched_from (live/wayback), is_truncated
- word_count, text_hash, fetched_at

Table live_entries: live blogs are stored once in articles AND split into their individual timestamped entries here (parent_id, entry_time, text, author if any), keeping only entries inside the date range.

Video/infographic pages: keep them even if the text is short, but mark them so they are easy to exclude.

Also save raw HTML gzipped in a separate folder, keyed by id, so we can re-extract later without re-downloading.
